## 1. Files and endpoint

```text
Controller: scripts\dho924_control.py
Tests:      scripts\test_dho924_control.py
Cache:      scripts\.dho_device_cache.json
DHO:        <dho-ip>:5555, or cached/discovered endpoint
Protocol:   Raw TCP SCPI, LF-terminated ASCII plus IEEE/TMC binary blocks
DHO ID:     RIGOL TECHNOLOGIES,DHO924,<serial>,<firmware>
MHO:        <mho-ip>:5555, or cached/discovered endpoint
MHO ID:     RIGOL TECHNOLOGIES,MHO934,<serial>,<firmware>
```

Run the examples from the bundled `scripts/` directory. Its `192.0.2.120` default is a documentation-only TEST-NET address, not a real instrument endpoint.

Discovery also probes common raw-SCPI ports 5025 and 4880. Generic SCPI devices receive only generic control.

## 2. CLI

```text
tui catalog discover idn status run stop single force autoset channel
acquisition timebase trigger measure counter dvm afg waveform screenshot
raw query write error
```

Read-only baseline:

```powershell
python dho924_control.py --host <dho-ip> idn
python dho924_control.py --host <dho-ip> status
python dho924_control.py status --channel 1
python dho924_control.py measure VPP --source CHAN1
python dho924_control.py measure FREQUENCY --source CHAN1
python dho924_control.py --host <mho-ip> acquisition
python dho924_control.py --host <mho-ip> afg --channel 1
```

Configuration examples, only when requested:

```powershell
python dho924_control.py channel --channel 1 --display ON --scale 500m --coupling DC --probe 10
python dho924_control.py timebase --mode MAIN --scale 10u --offset 0
python dho924_control.py trigger --mode EDGE --source CHAN1 --level 0 --slope POS --sweep AUTO
```

Generic parameters:

```powershell
python dho924_control.py query ":SYSTem:MODules"
python dho924_control.py write ":CURSor:MODE" MANual
python dho924_control.py raw ":TRIGger:MODE?"
```

Use `waveform` or `screenshot` for binary queries; ordinary `raw` expects text.

## 3. Python API

Import:

```python
from dho924_control import RigolDHO
```

High-value methods:

- Connection: `connect`, `close`, `reconnect`, `identify`, `query`, `write`, `query_block`.
- Channel: `channel_state`, `displayed_channels`, `configure_channel`.
- Acquisition: `acquisition_state`, `configure_acquisition`.
- Horizontal/trigger: `timebase_state`, `configure_timebase`, `trigger_state`, `configure_trigger`.
- Measurements: `measure`, `counter_state`, `configure_counter`, `dvm_state`, `configure_dvm`.
- MHO-specific: `afg_option_state`, `afg_state`, `configure_afg`, `synchronize_afg_phase`.
- Digital/display: `digital_state`, `display_state`.
- Data: `waveform_preamble`, `read_waveform`, `screenshot`.
- Actions: `run`, `stop`, `single`, `force_trigger`, `autoset`, `reset`.

Use `measure(item, source, source_b)` for dual-source delay/phase measurements.

## 4. TUI

Launch with no arguments:

```powershell
python dho924_control.py
```

The terminal UI contains 11 tabs. DHO exposes 136 entries; MHO expands the MHO/AFG tab for 159 entries total.

Controls:

- `1`-`4`: change the current edit channel only.
- Arrow keys or mouse: select.
- Enter/F2: execute.
- F5/R: refresh.
- Esc/Q: exit.
- Mouse wheel/PageUp/PageDown: scroll.

AUTOSET and reset require confirmation. Connection failure does not start an automatic rescan.

For waveform preview, the TUI checks the live CH1-CH4 display states. If the current edit channel is OFF and exactly one analog channel is ON, it switches the edit selection to that channel and logs the change. If several channels are ON, it asks the user to select one; it never enables a channel automatically.

## 5. Waveform and screenshot transfer

Screen waveform example:

```powershell
python dho924_control.py waveform --source CHAN1 --mode NORM --format WORD --points 1000 --csv ch1.csv
python dho924_control.py screenshot scope.png
```

Waveform sources include CHAN1-4, MATH1-4, and D0-D15. Formats are BYTE, WORD, and ASCII. WORD is decoded as unsigned 16-bit little-endian.

### DHO924 disabled-source behavior

Tested DHO924 firmware returns `-200,"Command execute failed"` when `:WAVeform:SOURce CHANnel<n>` names an analog channel whose display is OFF. It can return this error even when `:WAVeform:SOURce?` already reports that same disabled channel.

Use `RigolDHO.read_waveform()` instead of sending the setup sequence manually. It:

- queries the current waveform source and skips a redundant source write;
- checks `:CHANnel<n>:DISPlay?` before changing to another analog source and rejects an OFF target locally;
- compares mode, format, points, start, and stop before writing them;
- serializes source setup, preamble, and binary data under one connection lock.

When diagnosing this fault manually, use one TCP session and query the error queue after each command:

```text
:WAVeform:SOURce?
:CHANnel1:DISPlay?
:CHANnel2:DISPlay?
:CHANnel3:DISPlay?
:CHANnel4:DISPlay?
:WAVeform:PREamble?
:WAVeform:DATA?
:SYSTem:ERRor?
*IDN?
```

Do not assume `:WAVeform:POINts` or the IEEE block terminator is at fault without error-queue evidence. A verified DHO924 returns a 2000-byte block for 1000 WORD points, consumes the trailing LF correctly, accepts the follow-up `*IDN?`, and reports `0,"No error"` when an enabled source is used.

Conversions:

```text
time[i] = x_origin + (i - x_reference) * x_increment
voltage[i] = (sample[i] - y_origin - y_reference) * y_increment
```

RAW memory reads normally require the scope to be stopped. The controller does not automatically send STOP; obtain explicit authorization before changing acquisition state.

Screenshots use `:DISPlay:DATA? PNG|BMP|JPG` and IEEE/TMC definite-length blocks.

## 6. Supported boundaries

- High-level coverage includes CH1-4, model-aware acquisition, timebase, common trigger, 42 measurements, counter, DVM, digital state, display, waveform, screenshots, and MHO dual-channel AFG.
- DHO uses ULTRA acquisition parameters. MHO uses HRES and `:ACQuire:BITS 14|16`; never send DHO ULTRA parameters to MHO900.
- Use `query`, `write`, or SCPI console for hundreds of less-common leaf commands.
- DHO924 is not DHO924S. Do not present AFG or Bode functions as available DHO924 features.
- MHO AFG is option-dependent. Query `:SYSTem:OPTion:STATus? AFG100|AFG50` before relying on it, and never enable output without explicit permission.
- Valid timebase mode is MAIN/XY/ROLL; horizontal reference is CENT/LB/RB/TRIG/USER.
- Acquisition types are NORM/AVER/PEAK/ULTRA.
- DVM modes are ACRMS/DC/DCRMS.

## 7. Safety and validation

- Start with identity and status queries.
- Treat RUN/STOP/SINGLE, AUTOSET, reset, channel/acquisition/timebase/trigger writes, and RAW-memory preparation as state changes.
- Do not use AUTOSET during diagnosis unless explicitly requested; it changes multiple subsystems.
- Query `:SYSTem:ERRor?` after ambiguous raw writes.
- After waveform changes, confirm payload length, follow-up `*IDN?`, `0,"No error"`, and unchanged CH1-CH4 display states.
- Run `python -m unittest -v test_dho924_control.py` after controller changes.
- Use real-device write tests only with explicit authorization.
